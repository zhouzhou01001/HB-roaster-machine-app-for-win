# 调试日志说明（Roast Monitor）

本软件已内置后台调试日志模块：每次开始监测（非 SIMULATION）会自动创建一份会话日志文件（JSONL），用于真机联调问题回传与复盘。

## 日志文件位置

- 路径：`%APPDATA%\烘焙软件\data\debug_logs\`
- 文件名示例：`roast_debug_20260816_174500_123456_COM7_HB_TC4_batch12.jsonl`
- 在软件中可通过 **显示菜单 → 打开调试日志目录** 打开。

## 日志字段（每行）

- `session_id`：会话唯一 ID
- `sequence`：会话内序号
- `ts`：ISO 时间戳（UTC）
- `type`：事件类型
  - `session_start`：会话开始
  - `serial_raw`：原始串口行
  - `sample`：解析后的采样点（`payload.accepted`）
  - `sample_reject`：采样被拒绝（映射/质量门失败）
  - `parse_error`：解析错误
  - `serial_state`：连接状态变化
  - `serial_error`：采集异常
  - `serial_command`：发送到串口的控制指令（例如 CHAN;1300、READ）
  - `monitor_request`：开始监测参数
  - `reconnect_scheduled`：调度重连
  - `reconnect_attempt`：每次重连尝试
  - `reconnect_failed`：重连次数超限后失败
  - `monitor_stop`：停止监测动作
  - `session_stop`：会话结束
- `batch_id`：本次批次 id
- `source`：采集源（如 `COM7`）
- `source_details`：端口元数据（`usb_family`、`vid`、`pid`、`description`、`manufacturer`、`hwid` 等）
- `profile`：采集 profile（如 `HB_TC4`）
- `baudrate`：采集波特率
- `software_version`：软件版本
- `payload`：事件承载数据；`sample` 场景包含 `sample` 与 `accepted`；
  `parse_error` 与 `serial_error` 包含 `reason`、`raw_frame`、`parse_error_count` 等。

## 联调建议

- 仅把本轮有问题的 `debug_logs/*.jsonl` 回传给开发即可。
- 如果日志很大，可先运行：

```bash
python scripts/debug_log_summary.py debug_logs/xxx.jsonl --pretty
```

以快速确认是否存在解析错误、数据中断与重连失败，再把完整日志附上用于精修。

也可以直接给目录运行审计汇总：

```bash
python scripts/debug_log_audit.py "%APPDATA%\\烘焙软件\\data\\debug_logs" --pretty
```

该命令会按文件输出：
- 事件总量与事件类型分布
- 断连/采集异常/解析错误/重连失败计数
- `issue_type_counts`：按问题类型计数（如 `parse_error`、`reconnect_failed`）
- serial_command_count（发送指令数，含 READ/CHAN）
- reconnect_attempt_count（重连尝试次数）
- 最近异常列表（方便快速对照出现时间）
- 第一/最后异常时刻与问题总数（issue_count）

软件内的 **显示菜单** 也提供「导出调试诊断包」，会把当前会话日志与摘要打包到 zip，便于你直接回传。

### 外机联调回传动作（建议）

1. 先开启监测，确认左上角状态栏提示「调试日志已开启」且路径可见。
2. 出现温度异常、断连、采样中断等问题后，先在主页面点击「显示菜单 → 导出调试诊断包」。
3. 将导出的 zip 与本轮 `.hbroast` 数据一起带回。
4. 若未能导出当前会话，可打开日志目录，带回最近一条：
   - `%APPDATA%\\烘焙软件\\data\\debug_logs\\roast_debug_*.jsonl`
5. 回传后使用 `python scripts/debug_log_audit.py <日志目录> --pretty` 先给我看整体问题清单，再给我详细日志文件。

### 日志里可直接用于定位的数据字段

- `source`：如 `COM7`
- `source_display`：UI 显示串口文本（含厂商/描述）
- `profile`：协议模板（如 `HB_TC4`）
- `baudrate`：串口速率
- `session_id`：会话唯一 ID
- `batch_id`：批次 ID
- `payload.reason`：断连/解析错误原因
- `payload.raw_frame`：原始串口帧（保留 200 字）

`debug_log_summary.py` 对单文件会输出额外字段：
- `sample_reject_count`
- `reconnect_attempt_count`
- `reconnect_failed_count`
- `serial_command_count`

### 一键诊断包（建议给外机联调时使用）

在出现问题时，可直接打包完整排障材料（日志 + 摘要 + 每文件快速报表），便于你在外机联调后快速回传：

```bash
python scripts/export_debug_bundle.py "%APPDATA%\\烘焙软件\\data\\debug_logs" -o C:\\Temp -n roast_debug_issue_20260816
```

支持参数：
- `target`：日志文件 `roast_debug_*.jsonl` 或日志目录
- `--output/-o`：输出 zip 路径（不传则默认到目标目录下的 `bundle/`）
- `--name`：自定义压缩包名（不含 `.zip`）

压缩包内将包含：
- `logs/`：原始 jsonl 日志
- `summaries/`：会话摘要（若存在）
- `reports/`：每个日志的快速统计报表
- `manifest.json`：文件清单
- `debug_report.json`：汇总信息
