# 配置、部署与维护

## 已验证运行环境

- Windows 11 x86-64。
- HB Model S 通过已安装驱动的 USB-COM 设备连接。
- 显示器目标包含 1280x720、1920x1080、2K、2.5K、3K、4K；自动化测试不能替代每种缩放比例的人工视觉验收。
- 目标机运行 EXE 不需要 Python 或 VS Code。

## 设备配置

1. 开机确认烘焙机面板温度实时变化。
2. 插拔 USB 线，确认 Windows COM 端口同步消失和出现。
3. 配置 115200、8 数据位、无校验、1 停止位和短超时。
4. 先“开始采集”，确认豆温、进风温、出风温持续刷新，再“开始烘焙”。
5. 不允许将 0℃ 或空值当作断线后的真实温度继续记录。

## 配置与日志

- 用户配置和日志由应用服务层管理，实际目录应以程序界面或运行日志显示为准。当前版本不声明提供自动数据备份。
- 故障报告至少保留：发生时间、版本、COM 号、串口参数、设备面板温度、软件显示温度、日志和复现步骤。
- 不应手工编辑正式批次文件来修复现场问题；先复制原件再分析。

## 备份与恢复

1. 烘焙结束后立即保存 `.hbroast`。
2. 由用户定期把批次文件复制到另一磁盘或受控备份位置；程序不会替代该人工备份责任。
3. 恢复时先复制备份，不覆盖唯一原件。
4. 使用“载入备份/打开记录”验证曲线、事件、控制档位和元数据。
5. 只有载入备份曲线或当前烘焙结束后才允许导出 PDF。
6. 遇到旧格式或未知字段时停止批量迁移，保留样本并按 `09-数据格式兼容与迁移.md` 处理。

## 现场验收

| 检查 | 通过标准 |
|---|---|
| EXE 身份 | SHA-256 与 `release-metadata.json` 一致 |
| 启动 | 无 Python/VS Code 环境可启动，主界面完整 |
| 采集 | 三个业务温区持续刷新，值与设备面板合理对应 |
| 流程 | 采集、准备、入豆、事件、排豆状态切换正确 |
| 数据 | 入豆前数据不进入正式批次，断线不补造温度 |
| 文件 | 保存后可重新载入，结束后可导出 PDF |
| 显示 | 目标分辨率和缩放下无关键文字截断或按钮遮挡 |

## 故障恢复

- 串口未找到：重新插拔并核对设备管理器 COM 号。
- 串口占用：关闭 Artisan 或其他串口程序后重试。
- 通信超时/无反馈：核对波特率、设备开机状态、线缆和驱动。
- 烘焙中断线：保留计时，标记缺失区间，恢复后继续真实采集，不插值伪造数据。
- 程序异常退出：保留日志和最后一份人工保存的有效批次，不直接覆盖原文件；未保存数据不承诺可自动恢复。
