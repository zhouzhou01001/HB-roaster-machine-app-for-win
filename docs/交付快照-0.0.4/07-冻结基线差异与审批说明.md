# 0.0.4 与冻结基线的差异及审批说明

## 1. 基线处理原则

`docs/框架冻结基线-0.0.3` 和 `release/烘焙软件-0.0.3-设计文档基线` 保持原文、原目录和原校验文件。本文件只记录差异，供项目所有者审批是否创建新基线。

## 2. 主要差异

| 差异 | 0.0.4 当前事实 | 影响 |
|---|---|---|
| 操作流程 | 开始采集、开始烘焙、等待入豆、正式烘焙、完成 | 状态机和正式数据边界变化 |
| 时间零点 | 正式锅次从入豆 `00:00` 开始 | 样本、事件和 RoR 初始化变化 |
| 排豆后行为 | 正式记录停止，实时采集继续 | 会话与采集生命周期分离 |
| 坐标滚轮 | 滚轮永久不改变坐标 | 曲线交互变化 |
| 纵坐标 | 左右轴永久不显示负数 | 自动、持久化和拖动变化 |
| 排风温 | 新增 XT 正式曲线 | 曲线集合和快照变化 |
| RoR LCD | 整数显示，内部仍为浮点 | 展示精度变化 |
| 温度卡片 | 双行 RoR 与防裁切规格 | UI 组件变化 |
| 人工参数 | 滑块加宽，风门和转速 0-10 档 | UI 和记录变化 |
| 版本 | EXE、资源和运行时为 `0.0.4` | 发布身份变化 |

## 3. 建议审批动作

1. 将本差异合并进架构、流程和模块设计正式文档。
2. 以当前 5 态操作流替换旧流程，同时保留旧数据兼容边界。
3. 完成 Model S 通道专项验证后再冻结映射表。
4. 重新生成最终 UI 截图和分辨率证据。
5. 将 `139/139` 测试和 EXE 校验写入新基线。
6. 发布新基线身份，例如 `0.0.4-r1`。

收到明确审批前，本交付包不修改旧基线内容。
