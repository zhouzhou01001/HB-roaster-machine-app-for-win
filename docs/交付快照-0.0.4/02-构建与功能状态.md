# 构建与功能状态

## 构建对象

- 产品版本：`0.0.4`
- 可执行文件：`烘焙软件-0.0.4.exe`
- 入口：`main.py`
- GUI：PySide6
- 构建器：PyInstaller
- 已验证目标：Windows 11 x86-64
- 组装时的精确 Python、系统和依赖版本：交付包 `06-校验/dependency-versions.txt`

## 构建输入与输出

| 类型 | 内容 | 绑定方法 |
|---|---|---|
| 应用输入 | `main.py`、`app/**/*.py`、`scripts/build_exe.py`、版本文件、requirements | 路径和内容聚合 SHA-256 |
| 完整源码 | 代码、测试、脚本、当前文档、冻结基线、UI 资料 | 源码 ZIP SHA-256 |
| 测试输出 | JSON 报告和逐项文本输出 | 报告内应用源码聚合 SHA-256 |
| 运行制品 | Windows EXE | 文件 SHA-256 |
| 最终交付 | 完整交付 ZIP | 外部 `.sha256` 与 ZIP CRC |

本项目当前不以 Git 提交号作为交付身份；`release-metadata.json` 的 `git_commit` 明确为空。维护者必须使用源码归档哈希、应用源码聚合哈希和 EXE 哈希判定是否属于同一交付。

## 标准构建顺序

1. 安装 `requirements.txt` 中的运行与构建依赖。
2. 运行 `python scripts/run_release_tests.py`，生成绑定当前应用源码的测试证据。
3. 运行 `python scripts/build_exe.py` 构建 Windows EXE；如应用源代码未变化，可保留已验证制品，但必须重新记录其哈希。
4. 运行 `python scripts/assemble_delivery.py`。
5. 脚本拒绝测试失败、测试源码哈希不匹配、缺失 EXE、缺失冻结基线或基线复制哈希不一致的交付。
6. 脚本执行 ZIP CRC 自检并生成外部 SHA-256。

## 配置要求

- HB Model S 串口默认配置以用户确认的 Artisan 设置为依据：115200、8N1、短超时。
- COM 号必须与 Windows 设备管理器一致。
- CH431/USB 串口驱动不在交付包内。
- 配置和用户数据必须写入用户可写目录，不能依赖源码目录存在。

## 可复现性边界

PyInstaller 单文件构建会受到 Python、PyInstaller、依赖包版本和 Windows 工具链影响，因此“相同源码”不保证逐字节相同 EXE。本交付采用哈希绑定当前制品，而不是宣称任意机器都能产生同一二进制。重建时必须保留新环境报告并重新执行全部测试。
