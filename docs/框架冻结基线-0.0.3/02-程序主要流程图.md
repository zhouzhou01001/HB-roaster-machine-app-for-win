# 烘焙软件 0.0.3 程序主要流程图

## 1. 程序启动流程

```mermaid
flowchart TD
    A[执行 main.py] --> B[设置 High-DPI 缩放策略]
    B --> C[创建 QApplication]
    C --> D[ensure_workspace_dirs]
    D --> E{首选目录可写?}
    E -- 是 --> F[取得 data 与 config 目录]
    E -- 否 --> G[按候选顺序回退到 LocalAppData / Temp]
    G --> H{存在可写目录?}
    H -- 否 --> I[显示初始化失败对话框]
    I --> J[返回退出码 1]
    H -- 是 --> F
    F --> K[创建 MainWindow]
    K --> L[打开 SQLite 并执行 migrate]
    L --> M[加载通道映射和 QSettings]
    M --> N[创建状态机、缓冲区、串口管理器、质量门和 UI]
    N --> O{存在目录回退警告?}
    O -- 是 --> P[显示工作目录警告]
    O -- 否 --> Q[显示主窗口]
    P --> Q
    Q --> R[进入 Qt 事件循环]
```

启动异常路径：

- 缺少 PySide6 时，入口直接终止并提示安装依赖。
- 所有候选数据目录均不可写时，显示致命错误并返回 `1`。
- 数据库初始化时自动执行幂等迁移；已有字段导致的 `ALTER TABLE` 错误被视为已迁移并忽略。

## 2. 采集源选择与连接流程

```mermaid
flowchart TD
    A[用户选择采集源] --> B{来源为空?}
    B -- 是 --> C[拒绝启动并提示选择真实 COM 或 SIMULATION]
    B -- 否 --> D{来源为 SIMULATION?}
    D -- 是 --> E[显式启动 QTimer 模拟采样]
    D -- 否 --> F{profile 在支持列表?}
    F -- 否 --> G[发出未知协议错误]
    F -- 是 --> H{波特率为 9600 / 19200 / 115200?}
    H -- 否 --> I[发出波特率错误]
    H -- 是 --> J{pyserial 可用?}
    J -- 否 --> K[发出依赖缺失错误]
    J -- 是 --> L[serial_for_url 打开端口\ntimeout = 0.4s]
    L --> M{打开成功?}
    M -- 否 --> N[清理连接状态并发出错误]
    M -- 是 --> O[标记 connected]
    O --> P[启动 daemon 读取线程]
    P --> Q{profile}
    Q -- HB_MODEL_S --> R[进入 Model S 双通道组轮询]
    Q -- HB_TC4 / HB_LEGACY_3 --> S[进入 READ + 文本解析循环]
```

关键约束：模拟数据只能由用户显式选择；真实端口连接或重连失败时不得静默降级为模拟数据。

## 3. HB Model S 温度采集循环

```mermaid
flowchart TD
    A[读取线程 _read_loop] --> B{running 且 serial 存在?}
    B -- 否 --> Z[退出线程]
    B -- 是 --> C[reset 输入/输出缓冲]
    C --> D[发送 CHAN;1200 + LF]
    D --> E[等待 0.1 秒并读取确认]
    E --> F{确认为空或以 # 开头?}
    F -- 否 --> G[记录 CHAN 确认异常]
    F -- 是 --> H[继续]
    G --> H
    H --> I[发送 READ + LF]
    I --> J[等待 0.1 秒并读取三数值帧]
    J --> K{至少三个有限数字?}
    K -- 否 --> L[记录解析错误并放弃本轮]
    K -- 是 --> M[得到第一组 first]
    M --> N[用相同步骤请求 CHAN;3400]
    N --> O{第二组有效?}
    O -- 否 --> L
    O -- 是 --> P[组合四路业务原始数据]
    P --> Q[AT_RAW = first[0]]
    Q --> R[IT_RAW = first[2]]
    R --> S[CH4 = first[1]]
    S --> T[BT_RAW = second[1]]
    T --> U[ET_RAW = second[2]]
    U --> V[附加 SERIAL、端口、波特率、profile、原始帧和错误计数]
    V --> W[emit sample_received]
    W --> B
```

当前实现是串口文本命令轮询，不是 Modbus RTU/TCP。代码未构造 Modbus 功能码、站号、寄存器地址或 CRC。

## 4. 普通文本帧解析流程

```mermaid
flowchart TD
    A[收到一行文本] --> B{空帧?}
    B -- 是 --> X[拒绝并设置 last_error]
    B -- 否 --> C{READ 或 CHAN 命令回显?}
    C -- 是 --> X
    C -- 否 --> D{可解析为 JSON 对象?}
    D -- 是 --> E[_normalize_dict]
    D -- 否 --> F{声明了非摄氏单位?}
    F -- 是 --> X
    F -- 否 --> G{存在 KEY:VALUE / KEY=VALUE?}
    G -- 是 --> E
    G -- 否 --> H[按分号、逗号、空白拆分数字]
    H --> I{HB_TC4 且 5 数值?}
    I -- 是 --> J[time + CH1..CH4]
    I -- 否 --> K{HB_TC4 且 4 数值?}
    K -- 是 --> L[CH1..CH4 + 捕获时间]
    K -- 否 --> M{HB_LEGACY_3 且 4 数值?}
    M -- 是 --> N[time + CH1..CH3]
    M -- 否 --> O{HB_LEGACY_3 且 3 数值?}
    O -- 是 --> P[CH1..CH3 + 捕获时间]
    O -- 否 --> X
    E --> Q{含受支持温度通道且单位为 C?}
    Q -- 否 --> X
    Q -- 是 --> R[输出规范化字典]
    J --> R
    L --> R
    N --> R
    P --> R
```

## 5. 单个样本的核心处理流程

```mermaid
flowchart TD
    A[sample_received(raw)] --> B{workflow.acquisition_active?}
    B -- 否 --> Z[忽略]
    B -- 是 --> C[ChannelMapper.map_sample]
    C --> D{映射完整、无冲突且数值有限?}
    D -- 否 --> E[记录 sample_reject: channel_mapping]
    E --> Z
    D -- 是 --> F[合并原始审计字段与 it/et/bt/work]
    F --> G[SampleQualityGate.accept]
    G --> H{时间递增、温度在 -30..350、短时变化率 <= 80 C/min?}
    H -- 否 --> I[记录 sample_reject: 具体原因]
    I --> Z
    H -- 是 --> J[生成 time_ms 和 channel_mapping 文本]
    J --> K[calculate_ror: 最近窗口加权线性拟合]
    K --> L[写入 it_ror / et_ror / bt_ror 及兼容别名]
    L --> M[记录 accepted sample 调试日志]
    M --> N[追加到 RoastSessionBuffer.samples]
    N --> O[predict_ror: 未来 30 秒]
    O --> P[CurveWidget.set_data]
    P --> Q{自动 TP 开启且当前未记录 TP?}
    Q -- 是 --> R[detect_tp]
    R --> S{检测到回温点?}
    S -- 是 --> T[记录 TP 到内存]
    S -- 否 --> U[继续]
    Q -- 否 --> U
    T --> U[刷新实时指标、目标 ETA、发展阶段指标]
```

RoR 算法：

- 只取 `last_time - window` 之后的有效点。
- 按时间排序并合并同时间戳样本。
- 使用 NumPy 一次线性拟合，权重从 `0.35` 递增到 `1.0`，使新样本权重更高。
- 拟合斜率乘以 `60`，输出单位为 `°C/min`。
- 点数不足、时间无效或拟合失败时返回 `None`。

## 6. 烘焙会话状态机

```mermaid
stateDiagram-v2
    [*] --> IDLE
    IDLE --> ROASTING: start_acquisition\n第 1 锅
    ROASTING --> ROASTING: 记录/撤销非 DROP 事件\n记录人工操作和样本
    ROASTING --> AWAIT_END: 记录 DROP\n锁定事件
    ROASTING --> BETWEEN: 用户确认结束并归档\n允许无 DROP 结束
    AWAIT_END --> BETWEEN: 用户确认结束并归档
    BETWEEN --> ROASTING: start_next_batch\n批次号 +1，采集连接保持
    BETWEEN --> IDLE: stop_acquisition
    IDLE --> IDLE: 未选择来源或非法操作被拒绝
```

状态含义：

| 状态 | 采集 | 记录事件 | 结束当前锅 | 开始下一锅 | 停止采集 |
|---|---:|---:|---:|---:|---:|
| `IDLE` | 否 | 否 | 否 | 否 | 已停止 |
| `ROASTING` | 是 | 是 | 是 | 否 | 否，必须先结束锅次 |
| `AWAIT_END` | 是 | 否 | 是 | 否 | 否 |
| `BETWEEN` | 是 | 否 | 否 | 是 | 是 |

## 7. 事件记录、撤销与刷新流程

```mermaid
flowchart TD
    A[用户点击事件按钮] --> B{按钮当前是否已记录?}
    B -- 否 --> C[取得当前 time_s、IT、ET、BT、BT RoR]
    C --> D[RoastWorkflow.record_event]
    D --> E{状态、类型、重复和时间顺序合法?}
    E -- 否 --> F[恢复按钮展示并提示原因]
    E -- 是 --> G[events.add_event]
    G --> H[追加到内存并按时间排序]
    H --> I[刷新 EventPanel、CurveWidget 和发展指标]
    I --> J{事件为 DROP?}
    J -- 是 --> K[状态转 AWAIT_END，锁定事件，开放结束预览]
    J -- 否 --> L[保持 ROASTING]
    B -- 是 --> M{事件为 DROP?}
    M -- 是 --> N[拒绝撤销]
    M -- 否 --> O[RoastWorkflow.cancel_event]
    O --> P{允许撤销?}
    P -- 否 --> F
    P -- 是 --> Q[从内存事件列表删除该类型]
    Q --> I
```

同一事件类型只能保留一条。按钮第一次按下记录，第二次按下撤销；撤销后再次按下会按当前时间重新记录。`DROP` 一旦记录不可撤销。

## 9. 结束锅次与原子归档流程

```mermaid
flowchart TD
    A[用户点击结束当前锅] --> B{workflow.can_finish?}
    B -- 否 --> C[提示没有可结束锅次]
    B -- 是 --> D[复制 session_buffer.snapshot]
    D --> E[构造只读结束预览]
    E --> F[显示 PreviewCenterDialog]
    F --> G{用户确认?}
    G -- 否 --> H[丢弃 pending snapshot\n数据库不写入]
    G -- 是 --> I[RoastDatabase.archive_session]
    I --> J[BEGIN IMMEDIATE]
    J --> K[校验 samples/events/actions/metadata]
    K --> L[写 charges 完整 JSON 快照]
    L --> M[写 batches 摘要与 curve_snapshot]
    M --> N{两条记录都成功?}
    N -- 否 --> O[ROLLBACK]
    O --> P[保留当前状态和待确认数据，提示归档失败]
    N -- 是 --> Q[COMMIT]
    Q --> R[更新归档摘要]
    R --> S[workflow.finish_current_batch]
    S --> T[状态转 BETWEEN]
    T --> U[允许开始下一锅或停止采集]
```

## 10. 写入前确认门流程

```mermaid
flowchart TD
    A[导出 / 保存 / PDF / 配置确认] --> B[先收集脱离原对象的 snapshot]
    B --> C[PreviewCenterDialog 只读展示]
    C --> D{确认信号是否发出?}
    D -- 否 --> E[取消或关闭，不执行写回调]
    D -- 是 --> F{回调是否已执行或已取消?}
    F -- 是 --> E
    F -- 否 --> G[只执行一次 write_callback]
    G --> H{写入成功?}
    H -- 否 --> I[显示失败提示，保持对话框]
    H -- 是 --> J[接受并关闭对话框]
```

PDF 额外前置条件：当前烘焙已结束，或已载入背景/参考曲线。PDF 使用 Qt 矢量绘制当前可见曲线、坐标范围、事件线、目标线和图例，不依赖屏幕截图。

## 11. 断线重连与异常路径

```mermaid
flowchart TD
    A[串口错误或 state_changed false] --> B{会话仍 active 且不是 SIMULATION?}
    B -- 否 --> C[只更新状态]
    B -- 是 --> D{重试次数 < 5?}
    D -- 是 --> E[1.2 秒单次定时器]
    E --> F[重试次数 +1]
    F --> G[记录 reconnect_attempt]
    G --> H[按原端口、波特率和 profile 重连]
    H --> I{连接恢复?}
    I -- 是 --> J[清零重试并恢复采集状态]
    I -- 否 --> D
    D -- 否 --> K[停止重连定时器]
    K --> L[session_active = false]
    L --> M[断开串口并停止调试日志]
    M --> N[记录 reconnect_failed]
    N --> O[提示监测中止]
    O --> P[保留当前锅次内存数据]
```

主要异常处理基线：

| 异常点 | 处理方式 | 数据影响 |
|---|---|---|
| 串口打开失败 | 发出错误，进入有限重连 | 不切换模拟；内存锅次保留 |
| 半帧、空帧、字段不足 | 记录解析错误并跳过 | 不进入样本缓冲 |
| 通道映射冲突 | 记录拒绝原因并跳过 | 不污染曲线与归档 |
| 温度越界或尖峰 | 质量门拒绝 | 不污染曲线与归档 |
| 事件顺序冲突 | 抛出 `WorkflowError` 并恢复 UI | 事件列表不变 |
| 归档任一步失败 | SQLite 回滚 | `charges` 与 `batches` 均不产生半条记录 |
| 导出回调失败 | 显示警告 | 对话框不标记成功 |
| 应用关闭 | 停止重连、日志、串口并关闭数据库 | 已确认数据保留；未归档内存会话不会自动写入 |

## 12. 应用关闭流程

```mermaid
flowchart LR
    A[窗口关闭] --> B[停止重连定时器]
    B --> C[会话 UI 置为 inactive]
    C --> D[结束并汇总调试日志]
    D --> E[SerialManager.disconnect]
    E --> F[RoastDatabase.close]
    F --> G[交给 QMainWindow 完成关闭]
```
