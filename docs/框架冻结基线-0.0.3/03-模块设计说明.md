# 烘焙软件 0.0.3 模块设计说明

## 1. 文档目标与模块边界

本文档逐一记录当前产品源码模块、辅助脚本、构建配置和测试契约。每个模块均从职责、输入输出、主要接口、设计方法和交互关系五个角度说明。未列入产品架构的 `build/`、`dist/`、临时审计文件和 Codex 运行状态文件属于生成物或过程文件，不作为冻结框架的一部分。

## 2. 入口、版本与路径模块

| 模块 | 功能职责 | 输入与输出 | 对外接口 | 设计方法 | 主要交互 |
|---|---|---|---|---|---|
| `main.py` | 初始化 High-DPI、Qt 应用、工作目录和主窗口；进入事件循环 | 输入：命令行与系统环境；输出：进程退出码 | `main() -> int` | Composition Root；Fail Fast | 调用 `app.utils.paths`，创建 `MainWindow` |
| `app/version.py` | 提供唯一运行时版本号 | 输出：字符串 `0.0.3` | `APP_VERSION` | 单一版本常量 | 主窗口标题、调试日志、构建脚本 |
| `app/utils/paths.py` | 选择可写数据目录，创建 data/config/debug_logs，记录回退问题 | 输入：平台、环境变量、候选路径；输出：`Path` 或 `RuntimeError` | `ensure_workspace_dirs()`、`default_db_path()`、`default_channel_mapping_path()`、`default_debug_log_path()`、`get_workspace_issues()` | 候选链 + 可写探测 + 降级回退 | `main.py`、`ChannelMapper`、`SessionDebugLogger`、`MainWindow` |
| `app/__init__.py` | 标记产品包 | 无运行数据 | 无 | 包边界 | 被所有 `app.*` 模块隐式使用 |

## 3. 设备采集模块

| 模块 | 功能职责 | 输入与输出 | 对外接口 | 设计方法/算法 | 主要交互 |
|---|---|---|---|---|---|
| `app/device/hb_parser.py` | 将 JSON、键值对或数字文本帧转换为规范化原始通道字典 | 输入：原始文本、捕获时间、profile；输出：通道字典或 `None`，并设置 `last_error`/`last_format` | `HbParser.parse()`；`SUPPORTED_PROFILES` | Strategy by profile；宽输入、严输出；摄氏单位白名单 | 由 `SerialManager` 用于 HB_TC4/HB_LEGACY_3；Model S 双组帧路径绕过普通解析器 |
| `app/device/channel_mapping.py` | 将 `CH1..CH4` 或 `IT_RAW/ET_RAW/BT_RAW` 映射为 `it/et/bt/work/ambient` | 输入：原始样本、JSON 映射；输出：业务通道字典或 `None` | `ChannelMapper.load/save/set_mapping/map_sample`、`is_complete`、`mapping_text` | Adapter；冲突检测；有限数校验 | 由 `MainWindow._on_sample_raw` 调用；配置来自工作目录 `channel.json` |
| `app/device/serial_manager.py` | 枚举 COM、打开/关闭串口、后台读取、Model S 双通道组轮询、显式模拟采样、错误计数 | 输入：端口、波特率、profile；输出：Qt signals | `connect()`、`disconnect()`、`start_simulation()`、`available_ports()`；signals：`raw_received`、`sample_received`、`state_changed`、`command_sent`、`error`、`parse_error`、`parse_error_detail` | Facade + worker thread + Observer(Qt signals)；Model S Command/Response | 与 USB-COM、`HbParser`、`MainWindow`、调试日志连接 |
| `app/device/__init__.py` | 标记设备包 | 无 | 无 | 包边界 | 无直接业务逻辑 |

### 3.1 Model S 采集数据契约

| 字段 | 来源 | 业务意义 |
|---|---|---|
| `AT_RAW` | `CHAN;1200` 返回值 1 | 环境/辅助原始温度，当前不进入必需三通道 |
| `CH4` | `CHAN;1200` 返回值 2 | 可通过映射成为 `WORK`，当前 UI 用作出风温 |
| `IT_RAW` | `CHAN;1200` 返回值 3 | 进风温业务通道 `it` |
| `BT_RAW` | `CHAN;3400` 返回值 2 | 豆温业务通道 `bt` |
| `ET_RAW` | `CHAN;3400` 返回值 3 | 环境温业务通道 `et` |
| 审计元数据 | 串口管理器生成 | `source`、`port`、`raw_frame`、`baudrate`、`profile`、`parse_error_count`、`time_basis` |

## 4. 烘焙领域模块

| 模块 | 功能职责 | 输入与输出 | 对外接口 | 设计方法/算法 | 主要交互 |
|---|---|---|---|---|---|
| `app/roast/events.py` | 定义事件类型、去重并校验事件时间顺序 | 输入：事件列表、类型、时间；输出：已有事件、新事件或异常 | `EVENT_TYPES`、`MILESTONE_ORDER`、`validate_event()`、`add_event()` | 规则校验器；顺序约束 | `RoastWorkflow`、数据库、CSV 导入、主窗口 |
| `app/roast/workflow.py` | 管理连续采集下的多锅次状态；隔离内存会话数据 | 输入：用户动作和事件；输出：状态、批次号或 `WorkflowError` | `RoastWorkflow`、`RoastStage`、`RoastSessionBuffer` | State Machine；无副作用领域模型；Snapshot | `MainWindow` 负责驱动，`preview` 读取快照 |
| `app/roast/ror.py` | 计算 IT/ET/BT 的当前 RoR | 输入：样本序列和时间窗；输出：小写持久化键及大写兼容键 | `calculate_ror()` | 滑动时间窗 + 时间归一化 + 新样本加权线性回归 | 主窗口、趋势预测、测试 |
| `app/roast/projection.py` | 推算未来 RoR 曲线 | 输入：样本、未来秒数、窗口；输出：各通道 `(time, predicted_ror)` 列表 | `predict_ror()` | 先算 RoR，再拟合 RoR 对时间的线性趋势 | 主窗口曲线预测层 |
| `app/roast/sample_quality.py` | 拒绝无效时间、无温度、越界温度和短时尖峰 | 输入：映射后样本；输出：`SampleDecision` | `SampleQualityGate.accept/reset` | Stateful Gate；上一有效点对比 | 位于通道映射之后、RoR 之前 |
| `app/roast/compare.py` | 曲线对齐与误差指标；计算阶段地标；检测 TP | 输入：两组样本或事件；输出：MAE/RMSE/最大差、阶段指标、TP | `compute_curve_metrics()`、`roast_landmarks()`、`development_metrics()`、`detect_tp()` | 线性插值、统计指标、回温后单调恢复判定 | 对比窗口、主窗口自动 TP、分析模块 |
| `app/roast/milestone_forecast.py` | 依据最新正 RoR 预测转黄和一爆 ETA | 输入：当前样本与目标温度；输出：两个 ETA | `predict_milestone_times()` | 当前温差 / 最新正 RoR | `TargetPanel` 的 ETA 展示 |
| `app/roast/analysis.py` | 根据地标、样本和操作生成文字分析建议 | 输入：样本、事件、操作；输出：建议字符串列表 | `analyze_roast()` | 规则式分析 | 主窗口分析入口 |
| `app/roast/actions.py` | 规范化新旧人工操作字段并创建操作字典 | 输入：操作字典或数值；输出：统一字典 | `normalize_action()`、`add_action()` | Anti-corruption Adapter | JSON 导出、参考曲线、兼容旧数据 |
| `app/roast/manual_action.py` | 兼容转发人工操作创建函数 | 输入输出同 `add_action` | 导出 `add_action` | Compatibility Alias | 旧调用兼容 |
| `app/roast/configuration.py` | 定义不可变配置、配置差异和待生效配置状态 | 输入：配置字段变化；输出：候选配置、差异或验证异常 | `RoastConfiguration`、`RoastConfigurationState`、枚举类型 | Immutable Value Object + Transactional Staging | 配置对话框、主窗口部分运行配置 |
| `app/roast/importer.py` | 从 CSV 原子导入旧式锅次、样本和事件 | 输入：数据库和 CSV 路径；输出：roast id 或异常 | `import_csv_batch()` | Parser + Transaction；事件复用统一校验 | 主窗口导入入口、`RoastDatabase` |
| `app/roast/preview.py` | 生成结束、导出和配置差异的脱离式只读快照 | 输入：workflow、buffer 或配置字典；输出：深复制字典 | `build_end_roast_preview()`、`build_export_preview()`、`build_config_diff_preview()` | Builder + Defensive Copy | `PreviewCenterDialog`、测试契约 |
| `app/roast/reference_profile.py` | 将历史锅次保存为参考曲线，加载、列出和导出 profile | 输入：数据库记录、名称、目标文件；输出：profile id/字典/JSON | `save_profile_from_batch()`、`load_reference_profile()`、`list_reference_profiles()`、`export_profile_to_json()` | Repository helper + JSON Snapshot | 主窗口背景曲线和 profile 菜单 |
| `app/roast/replay.py` | 提供与 UI 无关的按速度遍历样本能力 | 输入：样本、播放速度、回调；输出：`ReplayFrame` | `RoastReplay.reset/set_speed/next/play/stop` | Iterator/Player | 当前 UI 回放窗口未直接复用该类 |
| `app/roast/__init__.py` | 标记领域包 | 无 | 无 | 包边界 | 无直接业务逻辑 |

## 13. 审查发现：耦合过重与设计不一致

### 13.1 高优先级

| 编号 | 发现 | 影响 | 建议的后续边界 |
|---|---|---|---|
| H-01 | `app/ui/main_window.py` 约 133 KB，同时承担 View、Controller、设备服务协调、会话状态、持久化、导出、日志、设置和重连 | 修改任一功能都可能触发跨域回归；难以独立测试和复用 | 后续若解冻架构，优先抽出 `AcquisitionController`、`RoastSessionService`、`ExportCoordinator` 和只读 ViewModel；MainWindow 只保留组合与呈现 |
| H-02 | 数据库同时保留旧式逐行模型和新式 `charges/batches` JSON 快照模型 | 相同锅次可能出现两套 id、字段和读取路径；回放/对比需要分支兼容 | 明确新功能唯一写模型；保留单向旧数据读取适配器，禁止双写 |
| H-03 | 通道映射存在三处语义来源：仓库 `channel.json`、`ChannelMapper` 默认值、Model S 组帧代码 | 配置缺失或被替换时，IT/ET/BT/CH4 可能表现不同；出风 `work` 依赖 CH4->WORK | 建立带版本的 `HB_MODEL_S` 固定映射 profile，并在连接页显示最终有效映射；启动时校验四路含义 |

### 13.2 中优先级

| 编号 | 发现 | 影响 | 建议的后续边界 |
|---|---|---|---|
| M-01 | `RoastConfiguration` 定义采样频率、保留天数、硬件协议等六项，但主窗口只实际接入主题、RoR 窗口和自动 TP 的一部分；配置对话框未完整接入主流程 | 界面或模型显示“可配置”不等于运行时真正生效 | 建立配置应用器，逐字段落实 `EffectiveTiming`，未接入字段不得暴露为可用设置 |
| M-02 | `sample_rate_hz` 未控制 Model S 读取循环；循环速度由两次 `sleep(0.1)`、串口读取和设备响应共同决定 | 配置值与真实采样周期可能不一致 | 使用受控调度器计算下一采样时刻，并记录实际采样间隔 |
| M-03 | `RoastReplay` 领域播放器与 `ReplayWindow` 的 QTimer 播放逻辑并存，后者未复用前者 | 两套播放速度、游标和停止规则可能漂移 | 让 UI 只驱动 `RoastReplay`，或删除未使用抽象 |
| M-04 | `database.models` 定义类型化 dataclass，但数据库和 UI 主路径仍大量交换可变字典 | 字段拼写、可选值和兼容键只能在运行时发现 | 在设备边界、会话边界和仓储边界逐步采用统一 DTO |
| M-05 | `CompareWindow`、`ReplayWindow` 直接访问 `RoastDatabase` 并各自处理 archive/legacy 分支 | 查询兼容逻辑重复，UI 与存储结构耦合 | 抽出 `RoastReadRepository` 或统一历史快照接口 |
| M-06 | 调试 ZIP 生成逻辑同时存在于 `SessionDebugLogger` 与 `scripts/export_debug_bundle.py` | 清单和统计字段可能不一致 | 抽出共享 bundle builder，GUI 与 CLI 共同调用 |
| M-07 | SQLite 使用 `check_same_thread=False`，但没有显式连接锁或单线程仓储约束 | 当前 UI 线程写入尚可；未来后台写入会产生并发风险 | 冻结为“仅 UI 线程访问”，或增加数据库 worker/锁 |

### 13.3 低优先级与维护性

| 编号 | 发现 | 影响 | 建议的后续边界 |
|---|---|---|---|
| L-01 | PyInstaller 配置使用绝对入口路径并 `collect_all` 整个 PySide6/pyqtgraph | 构建不可移植、EXE 约 268 MB，并收集无关 Qt/QML/3D 模块 | 使用相对路径、显式 hidden imports 和最小 Qt 插件清单 |
| L-02 | `requirements.txt` 只设最低版本，未锁定可复现构建版本 | 未来构建结果和行为可能漂移 | 发布基线增加 lock/constraints 文件和构建环境记录 |
| L-03 | `app/version.py`、`version_info.txt`、spec 名称需要手工同步 | 容易出现 UI 版本、EXE 属性和文件名不一致 | 构建时从单一版本源生成 Windows version resource |
| L-04 | 多处宽泛捕获 `Exception`，迁移和关闭路径部分静默忽略 | 真实故障可能只留下弱提示或无提示 | 区分可忽略兼容异常与必须记录的运行异常 |
| L-05 | 独立预览入口、流程面板、归档摘要、旧工具栏和曲线图例仍保留实现但主布局已隐藏或压缩 | 增加维护面和重复入口理解成本 | 保留“写入确认对话框”核心；对无入口组件明确标记实验性或删除 |
| L-06 | `source` 与 `data_source`、`port` 与 `source_port`、大小写 RoR 键并行保存 | 增加字段歧义和导出体积 | 定义 canonical 字段，兼容键只在导入/导出适配层出现 |

## 14. 冻结后的变更管理规则

以下变化必须视为“框架变更”，不得只修改代码而不更新基线：

- 新增、删除或移动产品模块。
- 改变 `MainWindow` 与设备、领域、数据库、导出模块之间的依赖方向。
- 改变 Model S 命令、换行符、通道组、通道含义或波特率支持范围。
- 改变样本 canonical 字段、质量门阈值、RoR 算法或单位。
- 改变事件集合、事件顺序、重复/撤销规则或 DROP 锁定规则。
- 改变四阶段状态机及确认后归档策略。
- 改变 SQLite schema、旧数据兼容策略或归档事务边界。
- 改变坐标轴归属、自动缩放、曲线显隐/粗细或 PDF 导出快照协议。
- 改变写入前确认门、连接失败不降级模拟、关闭时资源释放规则。
- 改变打包版本、依赖或 EXE 资源生成方式。

每次框架级变更至少应同步：三份基线文档、对应测试契约、版本记录和发布说明。

## 15. 审查结论

当前 0.0.3 已形成可运行的分层雏形：领域状态机、RoR、事件校验、质量门、串口管理、数据库归档和曲线组件均可独立识别；写入前确认和原子归档边界清楚。主要结构性风险集中在 `MainWindow` 高耦合、两套数据模型并存、通道语义多源配置和部分配置功能未真正贯通。冻结后若继续迭代，应先保持本基线行为不变，再通过新增服务边界逐步拆分，而不应在主窗口中继续累积跨域职责。

本次结论来自静态源码和测试契约审查；未在本轮重新执行全量测试，因此本文档是“当前代码结构与设计事实”的权威基线，不替代运行时验收报告。
