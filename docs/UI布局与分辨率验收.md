# UI 布局与分辨率验收说明

版本发布为 `0.0.0.3`。本轮调整统一图表、双纵轴、时间范围和曲线显示控制，不改变采集、事件、数据库和设备控制边界。

## 设计借鉴

- [Artisan 官方仓库](https://github.com/artisan-roaster-scope/artisan)：借鉴曲线、事件和实时状态围绕烘焙过程组织，低频显示和工具可按场景收起；没有复制代码、图标或品牌资产。该仓库为 AGPL-3.0，本项目只借鉴交互结构。
- [OpenRoast 官方仓库](https://github.com/Roastero/Openroast)：借鉴 Roast Graph 作为主视觉和简化控制区的优先级；没有复制 GPL-3.0 实现。
- [HiBean 官网](https://www.hibean.fun/en/) 与 [HiBean 文档](https://docs.hibean.fun/)：借鉴实时监控、设备连接、批次和分析分层的产品组织方式；HiBean 不是本项目的代码依赖。

## 当前布局策略

- 高频入口始终留在工具栏：开始监测、结束监测、新建批次、选择采集源。
- 打开、导入、保存、导出和批次信息收入“批次菜单”；背景曲线、显示设置和主题收入“显示菜单”；回放、对比、回温点和分析收入“曲线工具”。工具栏不再平铺全部动作。
- 主工作区保持曲线优先：状态/指标和一张统一主图在左侧同屏；BT/ET/IT 与人工操作归一化曲线使用左轴，RoR/预测 RoR 使用右轴，右侧事件、目标和人工操作控制区通过水平 `QSplitter` 调整宽度。
- 统一主图共享一个烘焙时间轴，事件线、目标线、背景 BT/RoR 和人工操作不会再被分割到第二张图。
- 主图控制条支持输入左右时间（秒），输入非法范围会拒绝并保留旧范围；鼠标拖动/缩放会回写输入框，手动应用范围会关闭自动跟随。
- “曲线显示”菜单提供 BT、ET、IT、各 RoR、预测 RoR、燃气、风门、转速和背景 BT/RoR 的独立显隐；全局及“单曲线线宽”菜单均支持细、标准、粗并立即刷新。
- 统一主图使用可压缩的最小/最大高度，不再使用 `500`/`180` 的固定最小高度。右侧事件列表最低高度降低到可在 720P 使用的范围。
- 首次窗口尺寸为 `1280x720`，图表和控制区使用 `Expanding` 策略；Qt 6 使用 `PassThrough` DPI 舍入策略，交给 Windows 100%/125%/150%/200% 缩放处理逻辑尺寸。
- 阶段按钮保持“名称 + 时间”文本，按钮不设置固定宽度，低频菜单和可拖拽分割栏避免挤压曲线。

## 几何探针

探针会输出实际窗口尺寸、`minimumSizeHint`、工具栏实际/提示尺寸、分割栏左右宽度、阶段按钮实际/提示尺寸、统一图表绘图区和 `clipped_or_invalid` 判断。

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
foreach ($scale in @("1", "1.25", "1.5", "2")) {
    $env:QT_SCALE_FACTOR = $scale
    python scripts/ui_geometry_probe.py | Out-File "ui-probe-$scale.jsonl"
}
Remove-Item Env:QT_SCALE_FACTOR -ErrorAction SilentlyContinue
```

验收分辨率：`1280x720`、`1920x1080`、`2560x1440`、`2880x1620`、`2880x1800`、`3840x2160`。每个 JSON 行的 `clipped_or_invalid` 应为 `false`，且统一图表绘图区、分割栏两侧宽度和阶段按钮实际宽高均为正数。

## 已知边界

物理屏幕在 200% DPI 下可能只有约一半的逻辑像素；任何桌面应用都不能在极小的逻辑桌面同时展示无限内容。本实现保证窗口不会因为固定图表高度和工具栏平铺而主动制造裁切，并保留分割栏拖动能力；极端小于验收规格的工作区仍应由操作系统窗口管理或用户临时最大化处理。
