# 周周 ROAST 优化验收清单

本清单由 `周周ROAST-完整操作文档.md` 提炼，用于本轮开发、测试和发布验收。

## 发布硬门槛

- [ ] 所有数据写入、导出、配置落盘均先生成只读预览，再由用户明确确认。
- [ ] 预览构建不触发数据库、文件、设备命令或运行状态变化。
- [ ] 项目 `tests` 测试集全绿后才能生成 EXE。
- [ ] 打包产物版本沿用当前产品版本，且不依赖用户电脑上的 Python 或 VS Code。

## 代码结构与可读性

- [ ] 采集、流程状态、预览快照、配置暂存、归档持久化和 UI 展示分层。
- [ ] 运行中采样、事件、手动操作只进入内存会话缓冲区。
- [ ] 流程状态只允许 `idle -> roasting -> await_end -> between` 的合法转换。
- [ ] 数据库归档以原子事务同时写入 `charges` 和 `batches`，失败时无半成品。
- [ ] 旧版 `roast_info/samples/events/manual_actions` 读取能力保持兼容。
- [ ] UI 组件不自行执行数据库、文件或设备 I/O；通过信号表达用户意图。
- [ ] 配置编辑使用副本与差异预览，采样频率等设置在下一锅生效。

## 主工作台与响应式布局

- [ ] 主界面采用顶部导航、流程条、LCD 卡片、主体工作区和底部操作栏的五区结构。
- [ ] 所有采集、事件、手动记录、曲线开关和归档摘要可在一个主画面操作。
- [ ] 右栏包含流程状态机、事件记录、手动控制和锅次档案四个模块。
- [ ] 720P、1080P、2K、2.5K、3K、4K 下无需主界面滚动即可完成实时烘焙操作。
- [ ] 宽度低于 1180px 时压缩右栏与 LCD；低于 980px 时 LCD 改为两行且控件仍可访问。
- [ ] 深色默认为仪表盘风格，浅色主题保持同一信息层级、状态色与可读性。
- [ ] 图标、按钮、数值和文字在高 DPI 下不截断，控件具备可访问名称。

## 采集、状态机与设备安全

- [ ] HB Model S 通道映射固定为 `CH1=ET`、`CH2=BT`、`CH3=IT`、`CH4=XT`。
- [ ] 设备仅用于读取温度；程序不下发燃气、风门、转速或任何设备控制命令。
- [ ] 开始采集自动开启第 1 锅；每锅确认结束后进入锅次间隙，采集连接不中断。
- [ ] DROP 只将状态转为待结束，不能自动停止串口读取。
- [ ] 仅空闲或锅次间隙允许停止采集；烘焙中与待结束必须阻止停止。
- [ ] 自动 TP 默认关闭，只有待确认配置生效后才能运行。

## 曲线、坐标与参数记录

- [ ] 主图呈现 BT、ET、IT、XT、四路 RoR、燃气、风门、转速及事件标记。
- [ ] 温度与人工记录使用左轴，RoR 使用右轴；控制量使用独立下方通道。
- [ ] X/Y 轴最小值、最大值和刻度间隔可设；烘焙中可随数据自适应缩放。
- [ ] 曲线可独立显示/隐藏并可配置线宽；历史曲线不叠加到实时主图。
- [ ] 燃气范围为 0–50 mbar、步长 0.5；风门与转速保留产品既定 0–10 档。
- [ ] 仅烘焙中记录参数变更点；空闲和锅次间隙允许调整当前值但不写入曲线。

## 事件与键盘交互

- [ ] 支持 `CHARGE`、`TP`、`YELLOW`、`FC_START`、`FC_END`、`SC_START`、`SC_END`、`DROP`。
- [ ] 除 DROP 外，重复点击同一事件取消其上次记录；`Z` 撤销最近一项可撤销事件。
- [ ] DROP 后事件与手动记录锁定，直到通过结束烘焙预览确认封存。
- [ ] Escape 可关闭所有只读预览，不产生副作用。

## 预览、归档、回放与导出

- [ ] 统一预览中心包含结束烘焙、导出曲线、保存批次、回放、锅次对比、配置变更六页签。
- [ ] 结束烘焙页签是唯一允许确认执行的页签；确认信号由主窗口处理。
- [ ] 导出 CSV 列固定为 `time_s,ET_C,BT_C,IT_C,XT_C,GAS_mbar,DAM,SPD`。
- [ ] PDF 导出只允许对当前已结束或已加载的备份曲线执行，先展示输出预览。
- [ ] 回放与对比仅读取归档快照，支持空档案、单锅和两锅数据，不修改归档内容。
- [ ] 锅次档案展示投豆量、时长、DROP、FC_START 及燃气/风门/转速操作次数。

## 性能与质量验证

- [ ] 采样回调不进行逐点 SQLite 提交，避免 I/O 抖动影响 1–10Hz 刷新。
- [ ] 大量样本的预览、归档、回放与对比使用快照和批量操作，避免重复读取。
- [ ] 每个新增状态机、预览、数据库、配置、UI 组件和只读视图均有针对性测试。
- [ ] 执行 `python -m pytest -q` 的项目测试范围，不收集工作目录中的第三方源码测试。
- [ ] 全量测试全绿后运行 `python scripts\\build_exe.py`，确认 EXE 产物存在。
